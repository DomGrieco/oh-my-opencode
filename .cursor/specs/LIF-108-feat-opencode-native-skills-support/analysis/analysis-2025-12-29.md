## Appendix B: OpenCode Native Skill System Reference

*From librarian research of OpenCode source code (sst/opencode)*

### Official Directory Structure

| Location | Glob Pattern | Notes |
|----------|--------------|-------|
| `.opencode/skill/` | `skill/**/SKILL.md` | Project-specific (walks up to git worktree) |
| `~/.config/opencode/skill/` | `skill/**/SKILL.md` | User-global skills |
| `.claude/skills/` | `.claude/skills/**/SKILL.md` | Claude Code compatibility |

### Discovery Order (First Match Wins)

```go
1. OpenCode directories (from Config.directories()):
   - ~/.config/opencode/skill/
   - .opencode/skill/ (walking up from CWD)
2. Claude-compatible directory (worktree only):
   - .claude/skills/
```

### Duplicate Handling

OpenCode **warns** on duplicate skill names (unlike our spec which chose silent deduplication per DD-4):

```typescript
if (skills[parsed.data.name]) {
  log.warn("duplicate skill name", {
    name: parsed.data.name,
    existing: skills[parsed.data.name].location,
    duplicate: match,
  })
}
```

**Implementation Note:** Our spec (DD-4) chose silent deduplication because duplicates are expected during migration. This is a deliberate deviation from OpenCode's behavior.

### Permission System (Out of Scope)

OpenCode supports skill-level permissions:
- `allow` / `deny` / `ask`
- Per-skill or glob patterns (`internal-*`: deny)
- Per-agent overrides

This was explicitly marked **out of scope** in the spec for future enhancement.
